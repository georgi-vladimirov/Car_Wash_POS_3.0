# Wash Depot – управление на автомивки

Уеб приложение за администриране на дейността на няколко автомивки. Работят с него касиерите на обектите.

## Как работим (ВАЖНО)
- **Потребителят пише кода сам.** Ти си помощник и ментор, не разработчик.
- Не създавай и не променяй файлове, освен ако не е поискано изрично.
- По подразбиране: обяснявай, давай кратки примери (до ~15 реда), прави ревю, посочвай рискове и грешки.
- Когато виждаш проблем (сигурност, пари, грешна логика), кажи го ясно, дори да не е питано.
- Отговаряй на български.

## Език
- **На английски:** имена в кода (модели, полета, функции, променливи, URL имена, шаблони), коментари, docstrings, commit съобщения.
- **На български:** всичко, което вижда потребителят: `verbose_name`, етикети, съобщения, текстове в шаблоните. Интерфейсът е само на български (`LANGUAGE_CODE = "bg"`), без i18n засега.
- Без транслитерация (`razhod`, `zaplata`). Понятията се превеждат според речника по-долу.

## Стек
- Django + PostgreSQL
- Фронтенд без API: HTML шаблони + **HTMX** (частични обновявания чрез Django views) + **Alpine.js** (поведение в браузъра) + **Tailwind CSS v4** + **DaisyUI v5**
- Календар: **Flatpickr** (български език, формат на показване `d.m.Y`, към сървъра `Y-m-d`)
- Пакети: `django-htmx`, `django-filter`; по желание `django-simple-history` (одит), `django-widget-tweaks`
- Не се ползва REST API и JavaScript фреймуърк (React/Vue).

## Предметна област
Четири основни панела: **Коли** (обслужени автомобили), **Разходи**, **Каса**, **Заплати**.
Касиерите въвеждат и услуги с цени, служители, локации и др.

### Основни модели (чернова)
Location, Service, ServicePrice (по категория автомобил, обект, валидна от дата), Employee,
Wash + WashItem, ExpenseCategory + Expense, CashShift + CashMovement,
PayrollPeriod + PayrollEntry + Advance.

### Речник (български → код)
Един термин за едно понятие навсякъде. Нов термин: първо се добавя тук.

| Български | В кода |
|---|---|
| Обект / автомивка | `Location` |
| Касиер / собственик | `cashier` / `owner` (роли) |
| Услуга | `Service` |
| Цена на услуга (ценова листа) | `ServicePrice` |
| Категория автомобил | `VehicleCategory` |
| Служител | `Employee` |
| Обслужена кола | `Wash` |
| Услуга в обслужването | `WashItem` |
| Разход / категория разход | `Expense` / `ExpenseCategory` |
| Смяна | `CashShift` |
| Касова операция | `CashMovement` |
| Начално салдо | `opening_balance` |
| Очаквано салдо | `expected_balance` |
| Крайно салдо | `closing_balance` |
| Баланс | `balance` |
| Разлика (липса/излишък) | `difference` |
| Период за заплати | `PayrollPeriod` |
| Ред във ведомостта | `PayrollEntry` |
| Аванс | `Advance` |
| Анулиране | `void` |
| Сторниране | `reversal` |
| Валидна от | `valid_from` |

### Правила за данните
- Пари: винаги `DecimalField`, никога float. Валута: евро.
- В `WashItem` се записва цената **към момента на продажбата** (старите отчети не се променят при нова ценова листа).
- Каса и заплати: одит на промените (кой, кога, какво). Вместо изтриване – анулиране/сторниране.
- Касата е вързана към **смяна** с начално и крайно салдо (очаквано спрямо реално преброено).
- Часова зона `Europe/Sofia`, `USE_TZ = True`.
- **Права:** касиерът вижда и редактира само данните на своя обект. Един общ филтър по обект за всички querysets (миксин в `core`), не отделни проверки.
- Всяка валидация (блокирани дати, права, суми) се прави и на сървъра. Интерфейсът не е защита.

## Структура
```
config/                  настройки (settings/base, dev, prod), urls
templates/               глобални: base.html, registration/, errors/, components/
static/src/app.css       вход за Tailwind (@import "tailwindcss"; @plugin "daisyui"; @source ...)
static/js/components/    dataTable.js, datePicker.js (Alpine компоненти)
static/vendor/           htmx, alpine, flatpickr (локално, не от CDN)
apps/core/               миксини, template tags (|money, |bgdate), context processors
apps/accounts, locations, catalog, staff, sales, expenses, cashbook, payroll
```
Шаблони на приложение: `apps/<app>/templates/<app>/` (папка със същото име).

## Конвенции за фронтенда
- Страница: `{% extends "base.html" %}`, попълва блоковете `title`, `content`, `extra_js`.
- **Фрагментите започват с `_`** (`_wash_table.html`) – това връща HTMX; страницата ги включва с `{% include %}`.
- View: цяла страница при нормална заявка, само фрагмент при `request.htmx`.
- CSRF за HTMX: `hx-headers='{"X-CSRFToken": "{{ csrf_token }}"}'` на `<body>`.
- Alpine компонентите се регистрират с `Alpine.data(...)` в `alpine:init`; скриптовете на компонентите са **преди** Alpine, с `defer`.
- Повтарящи се парчета: `templates/components/` или `{% include %}`, не собствен CSS.
- DaisyUI v5: няма `input-bordered`; много примери в интернет са за v4.

### Таблици (за четене)
Сървърът филтрира и връща до ~30–40 реда в `<tbody>`. В браузъра: само сортиране, филтър и експорт, без редакция на клетки.
Компонентът `dataTable` чете вече изрисуваните редове; датите и сумите носят `data-sort="..."` (ISO дата, число).
Експорт: CSV с разделител `;`, десетична запетая и BOM (Excel с български настройки). За истински `.xlsx` – генерира се на сървъра с `openpyxl`.

### Календар (Flatpickr)
`locale: 'bg'`, `altInput: true`, `altFormat: 'd.m.Y'`, `dateFormat: 'Y-m-d'`, период с `mode: 'range'`,
блокирани дати с `disable: [...]`, `minDate`/`maxDate`. Блокираните дати идват от базата (`json_script`).

## Ред на работа
1. Скелет: проект, PostgreSQL, потребители и роли, обекти
2. Каталог: услуги, цени, служители
3. Панел „Коли“ (най-често ползван, трябва да е бърз: малко кликове, автоматични цени)
4. Каса и смени → 5. Разходи → 6. Заплати → 7. Справки
